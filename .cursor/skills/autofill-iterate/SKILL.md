# 填充报告迭代

扩展每次一键填充后会生成一份报告（没填上的字段、填完仍为空的控件），经弹窗发到本机求职助手（`127.0.0.1:8001`）存进 `fill_reports` 表。这个流程把报告变成规则改进。

## 1. 拉汇总

```bash
curl -s http://127.0.0.1:8001/api/autofill/reports/digest | python3 -m json.tool
```

求职助手没开时请用户先打开它（扩展会把报告排队，下次连上再补发）。`reports` 为 0 说明自上次处理后没有新报告，告诉用户去多填几个网申页再来。

汇总里的分类（都已按「涉及网站数 → 是否必填 → 次数」排好序）：

| 分类 | 含义 | 怎么处理 |
| --- | --- | --- |
| `unknown` | 标签没匹配到任何字段 | 在对应 `*_DICT` 里加关键词；确实不该填的加进 `SKIP_LABEL` |
| `failed` | 认出了字段也尝试了，但没填上 | 看 `via`、`want`、`trace` 修填法或补值的别名 |
| `empty` | 认出了字段、简历也有值，但控件仍是空的 | 通常是区块 / 经历条数没对上，或填完被页面清掉 |
| `no_data` | 简历里没这一项 | 不改代码，汇总后提醒用户去选项页补简历 |
| `sites` | 每个网站的报告数和问题数 | 某个站问题特别集中时，可请用户在该页导出诊断信息 |

## 2. 改规则（都在 `content.js`）

- **字段关键词**：`BASIC_DICT` / `EDU_DICT` / `EXP_DICT` / `PROJECT_DICT` / `AWARD_DICT` / `CAMPUS_DICT` / `LANG_DICT` / `SKILL_DICT` / `CERT_DICT`（文件开头）。同一控件取最长命中的关键词，加短词前先想会不会误伤别的标签（例如「学历」会命中「第一学历类型」）。
- **跳过的字段**：`SKIP_LABEL`。
- **选项别名**：`prepare(resume)` 里给值加 `|` 分隔的候选，例如政治面貌、婚姻状况、工作年限。`failed` 里 `via: "choice"` 且 `trace` 是 `choice miss 选项A,选项B…` 时，对照 `want` 和页面选项补别名。
- **组件填法**：`via` 对应 `fillChoice`（下拉）、`fillCascade`（省市联动）、`fillDate`（日期面板）、`fillText`。`trace` 记录了每一步，`chain` 是控件的 DOM 祖先链，用来判断组件库。
- 报告里的 `‹简历›` / `‹隐私›` 是脱敏占位，不是页面原文，不要把它写进规则。

改完：

1. `node --check content.js`
2. `manifest.json` 的 `version` 加 0.1（报告里的 `version` 用来区分新旧规则产生的问题）
3. 汇总里出现的标签逐个过一遍：新规则会不会让别的已知标签匹配错

## 3. 收尾

1. 按仓库规范提交并推送（匿名身份、隐私钩子），提交说明写清修了哪些标签 / 组件。
2. 把这次处理过的报告标记为已解决（`ids` 来自汇总，只标这次看过的，以免吞掉新进来的报告）：

```bash
curl -s -X POST http://127.0.0.1:8001/api/autofill/reports/resolve \
  -H 'Content-Type: application/json' -d '{"up_to_id": <汇总里最大的 id>}'
```

3. 告诉用户：去 `chrome://extensions` 点扩展的刷新按钮，再在之前出问题的网站上试一次；`no_data` 里的字段请他在选项页补到简历里。

## 隐私

- 报告在扩展端已把简历里的文字换成 `‹简历›`，后端再抹一遍手机号、邮箱、身份证号；只保留性别、学历、政治面貌这类固定选项和日期。
- 回复用户、写提交说明时同样不要出现简历原文。
